# ADR-0008: Milestone 01A: EEG acquisition and protocol foundation

- Status: Accepted
- Date: 2026-10-30
- Decision Owner: Project owner (accepted explicitly in chat on 2026-10-30 after reviewing the verification report)
- Related Work: `docs/work/completed/WORK-2026-10-30-eeg-acquisition-protocol-foundation.md`
- Supersedes: None

## Context

Verified state before this change (`main` at `fdaf8ad`):

- `services/neuro-engine/src/neuro_engine/main.py` generated a 16-channel, 125 Hz sinusoid *inside each WebSocket handler*. Every client received an independent generator starting at `sequence=0`; nothing was acquired without a connected client (conflicts with ADR-0002/ADR-0004).
- `timestampMs` was wall-clock *send* time. Pacing used `sleep(block/fs)` after compute+send, so drift accumulated and slow clients slowed "acquisition". Values were rounded to 3 decimals. No provenance, unit, layout, gap or dropped-sample metadata. No `Origin` check on the loopback WebSocket.
- `packages/protocol` contained TypeScript interfaces only; the desktop did `JSON.parse(...) as EEGFrame` without runtime validation. ADR-0003 deferred the neutral schema choice to a feature ADR — this ADR is that feature ADR (it extends ADR-0003, not supersedes it).
- CI ran `lint test build` but not `typecheck`; Vite builds do not type-check.

Constraints: ADR-0001 (Nx + Yarn + uv), ADR-0002 (local-first, loopback, decoupled modules), ADR-0004 (raw recording independent of UI; replay through the same abstraction), ADR-0006 (renderers decoupled from acquisition).

## Decision

The owner approved the Milestone 01A plan (chat, 2026-10-30). Decisions:

1. **Canonical contract:** hand-authored JSON Schema (draft 2020-12) at `packages/protocol/schemas/eeg-stream.v2.schema.json` is the language-neutral source of truth. TypeScript validates against the same schema with Ajv and uses types generated by `json-schema-to-typescript` (committed; a test fails on drift). Python mirrors it with Pydantic v2 models (`strict`, `extra="forbid"`, camelCase aliases only on the wire). Non-finite values are rejected by the semantic layer in both languages, so both classify them identically. Python tests also check every fixture against the canonical schema with `jsonschema`. Shared valid/invalid fixtures under `packages/protocol/fixtures/v2/` are executed by both languages, with identical expected outcomes.
2. **Protocol v2** (breaking; `/ws/eeg` v1 and `EEGFrame` removed; no v1 recordings or external consumers exist). Messages: `stream.metadata`, `eeg.block`, `stream.status`, each with `type`, `schemaVersion: 2`, `streamId`. Strict validation (`additionalProperties: false`); producer and consumer ship in lockstep; unknown `schemaVersion` is classified as `unsupported-version`. Rules that JSON Schema cannot express (row count = channel count, row length = `sampleCount`, channel indices/labels, stream match) form a "semantic" layer implemented in both languages.
3. **Data semantics:** channel-major `samples[channel][sample]`; per-channel `unit` (`uV`) and `reference`; float64 transmitted without rounding (non-finite rejected). `firstSampleIndex` is a per-stream sample counter; `blockSequence` a per-stream transport counter; `droppedSamplesBefore` declares acquisition gaps; missing samples are never fabricated.
4. **Timebase:** engine-monotonic microseconds (`time.monotonic_ns() // 1000`, JSON-safe) with a `{monotonicUs, unixTimeUs}` anchor captured at stream open. `firstSampleTimeUs` estimates acquisition time of the first sample; sample *i* is at `firstSampleTimeUs + i·1e6/nominalSampleRateHz`. `timestampSource` declares meaning: `synthetic-nominal` (exact by construction), `host-receipt-fitted` and `device-clock` reserved for physical devices. Receipt/transmission time is never used as acquisition time.
5. **Device abstraction:** a small `DeviceAdapter` `typing.Protocol` (`open() -> StreamDescriptor`, `blocks() -> AsyncIterator[SampleBlock]`, idempotent `close()`), typed errors carrying a stable `code` and `retryable` flag (`DeviceConfigError` non-retryable; `DeviceConnectionError`/`DeviceDisconnectedError` retryable). Malformed adapter output (wrong channel count, non-finite values, duplicate or overlapping sample indices) is not an adapter error: the service rejects the block, counts it in `rejectedBlocks` and continues. `SampleBlock` is immutable (read-only float64 array, optional raw device timestamps reserved for the recorder). Adapters do no DSP, fan-out or reconnect decisions.
6. **Acquisition lifecycle:** `AcquisitionService` is started by the FastAPI lifespan, independent of clients. It owns the state machine (`idle, connecting, streaming, reconnecting, stopped, failed`), stream IDs, `blockSequence`, gap derivation from adapter sample indices, rejection of duplicate/overlapping/malformed blocks, capped exponential reconnect backoff (each reconnect opens a **new** `streamId`; the attempt counter resets after a session that delivered data), and counters. Non-retryable or unexpected errors end in `failed` (`/health` reports `degraded`); a source that ends normally ends in `stopped`.
7. **Synthetic source:** our own seeded deterministic generator (alpha 10 Hz + theta 6 Hz + Gaussian noise, per-channel phase) keyed by `(seed, block number)`, 16 channels at 125 Hz by default, with injectable `Clock` (`MonotonicClock`, `VirtualClock`) and absolute-deadline pacing (no cumulative drift). Fault plan supports `drop` and `disconnect`. Provenance (`generator`, `generatorVersion`, `seed`, `configHash`) is carried in metadata. BrainFlow (including its synthetic board) is deferred to milestone 01B.
8. **Streaming:** in-process `StreamHub` with non-blocking `publish()` and per-subscriber bounded queues. `live-view` policy drops the oldest block and counts it (reported per client in `stream.status`); `lossless` policy (reserved for the recorder) fails the subscription explicitly on overflow instead of blocking acquisition or dropping silently. Control events are bounded separately. Each WebSocket session serializes its own messages; serialization is not shared across clients (acceptable at one or two local clients; revisit if fan-out grows).
9. **Transport security:** server stays on `127.0.0.1`; the WebSocket rejects browser `Origin` values outside an allowlist (default Vite dev/preview origins on ports 4200/4300; configurable via `NEURO_ENGINE_ALLOWED_ORIGINS`). Rejection happens before accept (close 1008), which the ASGI server surfaces as an HTTP 403 handshake failure. Clients that send no `Origin` header (non-browser tools) are allowed. Client→server messages are not part of v2 and close the socket with code 1003.
10. **Desktop:** a non-React `EegStreamClient` validates every message, tracks integrity, reconnects with capped jittered backoff, detects stale streams and incompatible versions, and exposes `onBlock` for the future waveform buffer. React receives throttled status snapshots only; samples never enter React state. The placeholder sphere no longer maps a single sample to "activity".
11. **CI:** add `typecheck` to the CI `run-many` targets.

Signal-quality fields are deliberately excluded from v2 until an adapter can measure them (avoids fabricated quality values).

Implementation notes (2026-10-30): the plan proposed three ADR/work-record pairs (protocol, acquisition core, desktop client); implementation consolidated them into this single ADR and one work record because the three slices ship in lockstep (decision 2) and roll back as a unit. Rate fields are serialized as JSON numbers (`125.0` from Python). `effectiveSampleRateHz` is the sample-index advance per second of engine time since stream open (gaps included), `null` for the first second.

## Alternatives Considered

- **Schema:** Pydantic-first exported schema (Python becomes de facto source; noisy TS types); Protobuf + buf (extra toolchain, opaque wire format, unnecessary at 2 000 samples/s); Zod-first (TS-centric); keep TS interfaces + hand-written guards (guaranteed drift; violates ADR-0003).
- **Wire encoding:** binary Float32 frames or MessagePack — deferred until channel count × rate makes JSON measurably costly.
- **Device abstraction:** ABC hierarchies or entry-point plugins (premature); BrainFlow as the universal abstraction (cannot express deterministic synthetic data, replay, LSL or non-BrainFlow devices — becomes one adapter instead).
- **Synthetic source:** BrainFlow synthetic board — non-deterministic, real-time only, native dependency, and not 16 ch @ 125 Hz.
- **Timestamps:** keep wall-clock send time (wrong semantics); per-sample timestamps on the wire (heavier; kept internally for the recorder instead); nanoseconds (exceed 2^53 on long-uptime hosts).
- **Buffering:** shared ring buffer with per-consumer cursors (revisit for DSP windows); external broker such as Redis/ZeroMQ (new service); LSL as backbone (multicast conflicts with loopback-only default; native dependency).
- **Retain current approach:** per-connection generator — rejected because recording would depend on frontend connection state.

## Consequences

- Benefits: one canonical contract enforced at runtime on both sides; acquisition independent of clients; explicit time, unit, layout and provenance semantics; deterministic repeatable synthetic data; bounded memory; slow clients cannot delay acquisition; localhost stream protected from cross-site browser access.
- Costs: new dependencies — `ajv` (runtime, protocol package), `json-schema-to-typescript` (dev), `jsonschema` (Python dev); `pydantic` declared explicitly (already installed via FastAPI). The desktop bundle grows by the Ajv runtime (the production chunk is ~1.3 MB minified, dominated by Three.js; Vite warns above 500 kB). Hand-maintained Pydantic mirror (guarded by fixture parity tests). Ajv compiles validators with `new Function`, which a strict future Tauri CSP may forbid (follow-up: Ajv standalone precompilation).
- Breaking change: v1 clients no longer work.
- Scientific limits: synthetic timestamps are nominal and say nothing about real latency; physical-device timestamps (01B) will include unknown USB/BLE/radio buffering latency and crystal drift; no cross-device synchronization is provided. Synthetic data is labelled synthetic end-to-end.

## Validation and Rollback

Validation (commands and results recorded in the work record): protocol fixture parity in TS (Ajv + semantic layer) and Python (`jsonschema` + Pydantic); generated-type drift test; integrity scenario fixtures executed by TS and Python trackers with identical counters; synthetic determinism, spectral peaks and amplitude bounds; virtual-clock drift test over 10 000 blocks plus a short real-time rate test; hub backpressure tests; service lifecycle/fault tests (drop, disconnect → new stream, invalid config, malformed blocks); WebSocket integration (metadata first, schema-valid stream, shared indices across clients, acquisition without clients, Origin rejection, clean shutdown); desktop client tests with a fake WebSocket; `yarn nx run-many -t lint test typecheck build`; a real-process smoke test (uvicorn on `127.0.0.1`, real WebSocket client); governance checks.

Rollback: revert the change set as a unit (protocol, engine and desktop move together). Because no v1 recordings exist, no data migration is required. Future protocol changes require a new ADR and schema version.

## Corrections

- 2026-10-30: An independent review found that decision 1 (identical fixture classification in both languages) and decision 5 (rejection of malformed adapter output) did not hold for integral-float integers, `NaN` literals and protocol-limit violations. The `effectiveSampleRateHz` definition also depended on the index origin. The decision text above is unchanged; see ADR-0009 for the corrective decisions.
